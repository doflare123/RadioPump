# RadioPump — приложение

Клиент для существующего сервера RadioPump: Windows, macOS, Linux, Android и iOS.
Это ранняя версия. Приложение не запускает сервер и не хранит музыкальную библиотеку.

Инструкции: [на русском](../../docs/guide.ru.md#приложение) · [English](../../docs/guide.en.md#application).

## Запуск из исходников

Установите стабильный Flutter SDK и средства сборки нужной платформы. Из этой папки:

```sh
flutter pub get
flutter run -d windows --release
```

Вместо `windows` можно использовать `macos`, `linux` или ID подключённого телефона
из `flutter devices`. Для iOS и macOS нужен Mac с Xcode.

Проверка кода:

```sh
flutter analyze
flutter test
```

## Зависимости и обновления

Все версии, включая транзитивные, зафиксированы в `pubspec.lock`. При обновлении
нужно проверить эфир, остановку, быструю смену серверов, фон и системные кнопки.
HTTP и JSON используют Dart SDK; отдельного менеджера состояния и веб-движка нет.
Кеш системных обложек использует JSON-индекс вместо открытия SQLite.

| Группа | Назначение и дополнительные зависимости | Лицензии пакетов |
| --- | --- | --- |
| `just_audio`, `audio_session` | Один аудиоплеер и аудиофокус; интерфейсы платформ, RxDart, утилиты и плагины ОС | MIT / Apache-2.0 |
| `just_audio_windows` | WinRT MediaPlayer, без поставки отдельного FFmpeg; локальная копия 0.2.3 с поправкой распознавания live-потока | MIT |
| `just_audio_media_kit`, `media_kit_libs_linux` | Linux: libmpv, `media_kit`, FFI и нативные медиабиблиотеки; не инициализируются на остальных платформах | MIT у Dart-обёрток; отдельные лицензии поставляемых нативных библиотек |
| `audio_service`, `flutter_cache_manager` | Фоновое аудио и системное управление на Android/Apple; RxDart, кеш файлов и платформенные интерфейсы. Кеш также транзитивно объявляет `sqflite`, но клиент выбирает JSON-индекс | MIT |
| `window_manager`, `tray_manager`, `screen_retriever` | Размер и положение одного окна, системный трей, мониторы; `menu_base`, `path`, платформенные реализации | MIT |
| `shared_preferences` | Небольшие настройки; реализации платформ и `path_provider` | BSD-3-Clause |

Вариант без этих плагинов — поддерживать собственные интеграции Kotlin, Swift,
C++ и Linux, включая фоновые сервисы, media session и трей. Здесь выбраны готовые
интеграции; полный список лицензий доступен в стандартном диалоге Flutter.
Перед распространением Linux-сборки нужно включить уведомления и лицензии
фактически поставляемых libmpv/FFmpeg и других нативных компонентов.

## Ограничение ресурсов

- Один Flutter engine, окно и аудиоплеер; мини-плеер — другой режим того же окна.
- Только активный сервер: API каждые 5 секунд в окне, 20 секунд при фоновом
  воспроизведении. Скрытое остановленное приложение не опрашивает сервер.
- Нет загрузки библиотеки и очереди будущих треков. Ответ API ограничен 2 MiB.
- Декодирование обложки до 512 × 512, кеш изображений до 8 MiB / 12 записей.
  В мини-плеере обложка не создаётся; системная обложка ограничена 256 × 256.
  Для системных обложек на Android/Apple есть небольшой файловый кеш: восемь
  записей со сроком устаревания сутки, без хранения самого эфира.
- На Linux буфер демультиплексора ограничен 1 MiB; на Android заданы 2–8 секунд
  и целевой размер аудиобуфера 256 KiB. Это настройки компонентов, не предел RSS
  всего приложения. ОС и декодер могут выделять дополнительную память.
- Скрытый интерфейс не запускает секундный таймер прогресса. Нет постоянной
  анимации, предзагрузки треков или кеширования эфира на диск.

Сравнивать память нужно в `--release`: пустое окно, 10 минут эфира, скрытый
плеер, повторные переключения волн и серверов. Debug-сборка содержит средства
разработки и не подходит для оценки памяти конечного приложения.
