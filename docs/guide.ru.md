# Руководство RadioPump

[На главную](../README.md) · [English](guide.en.md)

## Первый запуск

Нужен Docker с Compose; в Docker Desktop используйте Linux containers. Скачайте и распакуйте проект. Все команды ниже выполняйте в папке с `docker-compose.yaml`. На Windows используйте PowerShell, на Linux и macOS — терминал.

1. Скопируйте `.env.example` в той же папке и назовите копию `.env` (не `.env.txt`).
2. Откройте `.env` текстовым редактором.
3. После `RADIOPUMP_ADMIN_PASSWORD=` впишите уникальный пароль минимум из 12 латинских букв, цифр или знаков. Заключите значение в одинарные кавычки.
4. Получите отдельный случайный ключ командой:

```sh
docker run --rm debian:bookworm-slim sh -c "od -An -N32 -tx1 /dev/urandom | tr -d ' \n'"
```

Скопируйте полученную строку из 64 знаков после `RADIOPUMP_JWT_SECRET=`. Это служебный ключ для входа администратора; запоминать его не нужно. Не используйте вместо него пароль. Остальные строки пока оставьте как есть. Не выкладывайте `.env` в общий доступ.

Запустите радио:

```sh
docker compose up -d --build --wait
```

Первый запуск скачает и соберёт необходимые программы. Откройте [http://localhost:8080/](http://localhost:8080/). Радио работает, пока включены компьютер и Docker, даже если закрыть терминал.

## Добавление музыки

1. Откройте [вход администратора](http://localhost:8080/admin-login.html). Логин — `admin`, пароль — заданный в `.env`.
2. В разделе треков выберите файл. Дождитесь заполнения названия, исполнителя, альбома и длительности.
3. Исправьте поля при необходимости. Если названия в файле нет, используется имя файла.
4. При желании выберите теги станции, например `rock` или `ambient`.
5. Нажмите **«Загрузить»**. До этого момента файл остаётся на вашем устройстве.
6. Вернитесь на главную и включите волну `Main`.

Вместе с треком сохраняется найденная обложка. Без неё отображается пластинка. Дополнительные сведения вроде года и жанра можно посмотреть перед загрузкой, но они пока не сохраняются в библиотеке.

Принимаются MP3, MP2, FLAC, WAV, Ogg, Opus, M4A/MP4, AAC, AIFF, WMA, APE, WavPack, Musepack, MKA/WebM, DSF и DFF. Повреждённый файл может загрузиться, но не воспроизводиться. По стандартным настройкам один файл может занимать до 100 МБ. Загрузка должна завершиться за 60 секунд.

В списке загруженных треков можно изменить поля и теги или удалить трек. Удаление убирает и сохранённый на сервере аудиофайл. Простое копирование музыки в папку не добавляет её в радио — используйте форму загрузки.

## Волны и теги

Тег — ваша метка для отбора музыки. Его можно назначить нескольким трекам. Создавайте свои метки в **«Справочнике тегов станций»** внизу страницы администратора. Теги из самого аудиофайла не назначают трек волне автоматически.

Чтобы добавить волны:

1. Скопируйте `config.example.yaml` в `config.production.yaml`.
2. Добавьте в `.env` строку `RADIOPUMP_CONFIG_PATH=./config.production.yaml`.
3. В `config.production.yaml` замените раздел `waves`:

```yaml
waves:
  - name: Main
    tags: []
  - name: Chill
    tags: [lo-fi, ambient]
  - name: Rock
    tags: [rock, metal]
```

`Main` играет всю библиотеку. `Chill` — треки с тегом `lo-fi` **или** `ambient`. `Rock` — с тегом `rock` **или** `metal`. Имена волн должны отличаться. Собственные теги сначала создайте в админке и назначьте трекам. Сохраняйте отступы пробелами, как в примере.

Примените настройки:

```sh
docker compose up -d --force-recreate --wait
```

Тег, указанный в настройках волны, нельзя переименовать или удалить. Сначала уберите его из файла настроек и выполните команду выше.

## Другие настройки

Docker по умолчанию читает `config.example.yaml`, а не `config.yaml`. Для изменений используйте свою копию, как в разделе выше.

| Где менять | Что делает |
| --- | --- |
| `.env`: `RADIOPUMP_ADMIN_NAME` | Логин администратора. По умолчанию `admin`. |
| `.env`: `RADIOPUMP_ADMIN_PASSWORD` | Пароль администратора. |
| `.env`: `RADIOPUMP_PORT` | Порт сайта. Если 8080 занят, поставьте 8081 и открывайте `http://localhost:8081/`. |
| `config.production.yaml`: `music.max_file_size_mb` | Максимальный размер одного файла в МБ. Браузер читает файлы до 512 МБ. |
| `config.production.yaml`: `stream.bitrate` | Качество звука и расход трафика. По умолчанию `128k`. |

После изменений выполните команду применения настроек выше. В Docker оставляйте `server.port: 8080` и `music.dir: ./music`. Остальные параметры можно не трогать.

Чтобы сменить пароль и завершить уже открытые входы администратора, замените одновременно пароль и случайный ключ в `.env`, затем примените настройки.

## Доступ с телефона или другого компьютера

Для устройств в одной сети поставьте в `.env`:

```dotenv
RADIOPUMP_BIND=0.0.0.0
```

Примените настройки. Узнайте локальный IP компьютера с радио в настройках сети. На другом устройстве откройте, например, `http://192.168.1.50:8080/`, подставив свой IP. Если сайт не открывается, разрешите входящие подключения к выбранному порту в настройках брандмауэра.

## Приложение

В `apps/radiopump` находится ранняя версия приложения на Flutter для Windows,
macOS, Linux, Android и iOS. Оно подключается к уже работающему серверу; музыка
по-прежнему хранится и транслируется сервером. Готовых публикаций в магазинах пока нет.

Для запуска из исходников установите Flutter и средства сборки своей платформы:

```sh
cd apps/radiopump
flutter pub get
flutter run -d windows --release
```

На Mac используйте `-d macos`, на Linux — `-d linux`. Для телефона найдите его
ID командой `flutter devices` и укажите вместо `windows`. Для iOS нужен Mac с Xcode.
Если Windows сообщает, что нужны символические ссылки, включите режим разработчика
Windows и повторите команду.

1. Нажмите «Добавить радио», задайте название и полный адрес сервера, например
   `https://radio.example.org` или `http://192.168.1.10:8080`.
2. Выберите волну и нажмите кнопку воспроизведения. Вход администратора не нужен.
3. Чтобы слушать радио другого владельца, добавьте его сервер и выберите его
   название в верхней части окна. Переключатель меняет сервер, список — его волны.

Стрелки переключают волны, а не треки общего эфира. Полоса показывает время
текущего трека; перемотки и воспроизведения истории нет. После остановки следующее
включение возвращает в текущий эфир. Название и обложка могут немного опережать звук.

На компьютере закрытие окна скрывает его в трей, если трей доступен. Нажатие
значка открывает мини-плеер; «Развернуть» возвращает полное окно. Для завершения
приложения выберите «Выход» в меню значка. Без поддержки трея закрытие завершает
приложение. На некоторых Linux-окружениях для трея требуется поддержка AppIndicator.

На телефоне используется один основной экран; для фонового управления предусмотрены
уведомление Android и системный плеер iOS. Работу в фоне и после звонков нужно
проверять на реальном телефоне: подготовка проекта ещё не означает проверку всех ОС.
Не сравнивайте память debug-сборки с готовыми приложениями: используйте `--release`.

Загрузка музыки и управление библиотекой остаются в веб-интерфейсе.

## Доступ через интернет

Нужны сервер с доступом из интернета и домен. Пароль защищает управление библиотекой; прослушивание и исходные аудиофайлы доступны без входа.

1. Укажите IP сервера в записи A домена. Запись AAAA нужна только при работающем IPv6.
2. Откройте порты 80 и 443 на сервере и, при необходимости, маршрутизаторе.
3. В `deploy/Caddyfile` замените `radio.example.com` своим доменом.
4. В `.env` оставьте `RADIOPUMP_BIND=127.0.0.1`.
5. Выполните:

```sh
docker compose -f docker-compose.yaml -f compose.https.yaml up -d --build --wait
```

Caddy — программа, которая принимает подключения к вашему домену и включает защищённый доступ HTTPS. Она запускается этой командой и получает сертификат автоматически. Открывайте `https://ваш-домен/`. Размещайте радио на отдельном домене или поддомене, не по адресу вида `/radio/`.

Для этой установки во всех дальнейших командах заменяйте `docker compose` на `docker compose -f docker-compose.yaml -f compose.https.yaml`, сохраняя остальные параметры. Проверьте вход, загрузку и несколько минут прослушивания через свой домен.

## Остановка и запуск

```sh
docker compose stop
docker compose start
```

Первая команда останавливает радио, вторая запускает снова. Данные сохраняются. Для запуска после перезагрузки компьютера Docker должен запускаться вместе с системой. Радио, остановленное вручную, нужно включить командой `start`.

Музыка и сведения о ней хранятся отдельно от приложения, в хранилищах Docker `music` и `data`. **Не выполняйте `docker compose down -v`: это удалит библиотеку.** Не меняйте имя папки проекта после установки: Docker может выбрать другое хранилище, и библиотека будет выглядеть пустой.

## Сохранение копии данных

На время копирования эфир остановится. Сохраняйте музыку и сведения о ней вместе.

1. Создайте в папке проекта новую папку `backups/before-update`. Для следующей копии выберите другое имя и замените его в команде.
2. Выполните по очереди:

```sh
docker compose stop radio
docker compose run --rm --no-deps --user 0:0 --cap-add DAC_OVERRIDE --volume "./backups/before-update:/backup" --entrypoint tar radio -czf /backup/library.tar.gz -C /app data music
docker compose start radio
```

Вторая команда должна завершиться без ошибок. Если она не удалась, снова запустите радио последней командой, устраните ошибку и повторите копирование. Не считайте неполный архив готовой копией.

3. Скопируйте в `backups/before-update` файл `.env`, используемый файл настроек и, если подключён домен, `deploy/Caddyfile`. Сохраните также исходники текущей версии проекта.
4. Сохраните готовую программу, чтобы можно было вернуться к этой версии:

```sh
docker image save -o backups/before-update/image.tar radiopump:local
```

Перенесите всю папку копии на другой диск. В ней есть пароль — ограничьте доступ к ней.

## Восстановление копии

Эти команды предназначены для копии установки Docker. Перенос библиотеки, ранее запущенной напрямую в Windows, этим способом не поддерживается.

1. В отдельную папку поместите сохранённые исходники, `.env` и файлы настроек на прежние места. Положите архив и сохранённую программу в `backups/before-update`.
2. В `.env` поставьте свободный порт, например `RADIOPUMP_PORT=18080`. Откройте терминал в этой новой папке.
3. Выберите новое имя установки, которое раньше не использовалось. В примере это `radiopump-restored`. Не восстанавливайте архив поверх существующей библиотеки.
4. Выполните по очереди, переходя к следующей команде только после успеха предыдущей:

```sh
docker image load -i backups/before-update/image.tar
docker compose -p radiopump-restored run --rm --no-deps --user 0:0 --cap-add DAC_OVERRIDE --cap-add CHOWN --cap-add FOWNER --volume "./backups/before-update:/backup:ro" --entrypoint tar radio -xzf /backup/library.tar.gz -C /app
docker compose -p radiopump-restored up -d --no-build --wait
```

Для проверки на том же компьютере используйте только основной `docker-compose.yaml`, без файла HTTPS: порты домена заняты прежней установкой. Откройте [http://localhost:18080/](http://localhost:18080/), проверьте вход, треки, теги, обложки и звук. В дальнейшем добавляйте `-p radiopump-restored` ко всем командам этой установки. История воспроизведения после запуска начинается заново.

## Обновление

1. Сделайте копию по инструкции выше и проверьте её восстановление.
2. Скачайте новую версию проекта. Замените исходники в прежней папке, сохранив свои `.env`, `config.production.yaml` и `deploy/Caddyfile`.
3. Выполните:

```sh
docker compose build --pull
docker compose up -d --wait
```

4. Проверьте вход, список треков, загрузку и звук.

Если новая версия не работает, восстановите прежнюю программу вместе с её копией данных в отдельную установку по инструкции выше. Не запускайте старую версию на данных, уже изменённых новой. После проверки остановите новую версию и настройте прежней нужный порт или домен.

## Если что-то не работает

Посмотреть состояние и последние сообщения:

```sh
docker compose ps
docker compose logs --tail=100 radio
```

| Проблема | Что сделать |
| --- | --- |
| Не запускается, ошибка пароля или ключа | Проверьте обе заполненные строки в `.env`. |
| Порт занят | Измените `RADIOPUMP_PORT` в `.env` и примените настройки. |
| Волна пустая | Загрузите трек. Для тематической волны назначьте ему подходящий тег. |
| Трек пропускается или звука нет | В админке откройте «Состояние эфира» → «Обновить диагностику». Повреждённые файлы временно пропускаются; замените проблемный трек. |
| Файл не загружается | Проверьте формат, размер, свободное место и скорость сети. На передачу отведено 60 секунд. |
| Вход временно заблокирован | После частых попыток подождите минуту и повторите. |
| После переноса папки пропала библиотека | Верните прежнее имя папки и используйте прежнюю установку Docker. |
| Библиотека занята | Остановите второй экземпляр радио, использующий те же данные. |
| Домен не открывается | Проверьте адрес домена, порты 80/443 и сообщения `docker compose -f docker-compose.yaml -f compose.https.yaml logs --tail=100 proxy`. |

Плавные переходы между треками, выравнивание громкости и музыка-заглушка для пустой волны пока отсутствуют. Работа сутки подряд и с сотнями слушателей ещё не проверена.
