# Страница живого радио

Реализовано 2026-09-05. Главная показывает станции в порядке `waves` из
`config.yaml`: название, теги, кнопку включения, текущий трек, исполнителя,
альбом, время и обложку. Без обложки — пластинка, которая вращается во время
прослушивания (с учётом `prefers-reduced-motion`). Светлая/тёмная темы сохранены.
Нижняя ручка раскрывает последние пять треков и следующие пять позиций.

Файловый плеер удалён из публичного интерфейса. Старые `player.html`,
`library.html`, `waves.html` перенаправляют на главную; административная библиотека
сохраняет загрузку, редактирование и удаление. Прямой `/music/*` по-прежнему
доступен для совместимости, но страница радио его не использует.

## Состояние и очередь

`GET /api/radio` — публичный JSON со временем сервера `server_time` и массивом
`stations`. Станция содержит `id`, `tags`, `current`, `started_at`, `history`,
`queue`. Публичный трек: `id`, `title`, `artist`, `album`, `duration`,
`cover_url`, `started_ms`, `ended_ms`. Путей библиотеки и бинарных обложек нет.
У будущих позиций временные метки нулевые; у текущего `ended_ms` равен нулю.

Playback помечает трек текущим только после первого чанка аудио. Завершившиеся
или прервавшиеся после начала аудио треки попадают в историю, новые первыми.
Ошибка до появления аудио историю не создаёт. История общая для слушателей,
ограничена пятью записями в памяти каждой станции и исчезает при перезапуске.
В SQLite история не записывается.

Scheduler заранее планирует не менее пяти следующих позиций, включая переход
между циклами. Snapshot не потребляет очередь. В маленькой библиотеке будущие
повторы отображаются честно. Изменение библиотеки/тегов может изменить очередь
при следующем выборе; удалённые записи не показываются, после ошибки чтения
worker продолжает эфир с существующим backoff.

Страница опрашивает состояние раз в две секунды, с таймаутом 8 секунд и повтором
через 5 секунд при ошибке. Это обычный HTTP, без WebSocket и новых зависимостей.
Часы интерфейса используют время сервера и монотонное время браузера; остановка
обновлений помечается как устаревшее состояние. Данные аудио от этих запросов
не зависят.

## Подключение

На странице один `Audio`. Выбор станции подписывает его на `/stream/{name}`;
выбор другой освобождает предыдущую подписку. Ни обновление карточек, ни
раскрытие истории, ни подключение нового участника не запускают новый encoder.
Остановка освобождает поток; повторное включение возвращает в прямой эфир.
Encoder дополнительно ограничивает выдачу байтов по фактическому CBR bitrate
MP3 frame, включая ожидание конца последнего чанка: начальный burst FFmpeg
не должен накапливать опережение при повторении коротких треков.

При ошибке/EOF — повтор с экспоненциальной задержкой 1–30 секунд и jitter.
При отсутствии прогресса аудио более 20 секунд срабатывает watchdog. Без сети
повторы ждут события `online`. Ручная остановка отменяет retry; поздняя ошибка
старой попытки не может переключить новую станцию. Отказ браузера разрешить
звук просит нажать кнопку, а не вызывает бесконечный autoplay.

HTMLAudio не предоставляет точную серверную временную метку первого MP3 frame.
Для выбранной станции положение оценивается по `currentTime`, доступному
`buffered` и серверным часам. История переходов позволяет задержать смену
названия/обложки до слышимого трека. Это приблизительная синхронизация: сетевой
буфер, задержки декодера и паузы между процессами FFmpeg могут давать погрешность.
У остальных станций показан текущий серверный эфир.

Пустая станция ожидает музыку; генератора тишины нет. Gapless/crossfade,
нормализация, сохранение воспроизведения при переходе в отдельную админскую
страницу и длительная сетевая нагрузка остаются вне этого этапа.

## Обложки

До submit выбранный файл и обложка остаются в браузере. При явной загрузке
preview нормализуется через Canvas в JPEG до 1024 пикселей по большей стороне
и добавляется частью `cover` в multipart. Ошибка декодирования оставляет трек
без обложки. Основные ручные поля имеют прежний приоритет.

Сервер принимает исправный JPEG/PNG до 2 MiB и 2048×2048, проверяя размеры до
полного декодирования. Миграция №3 создаёт `track_covers(track_id, data)`.
Вставка/удаление обложки выполняется в той же транзакции, что и трек. Неизвестный
тег откатывает обе записи; файловый rollback остаётся прежним.

`GET /api/covers/{id}` публично возвращает изображение с `nosniff` и кешем на
час. JSON трека содержит `CoverURL`; бинарные данные в списки не включаются.
Ранее загруженные файлы и JSON-импорт обложек автоматически не получают.
Расширенные встроенные поля по-прежнему доступны только в preview.

## Проверка

- `go test ./... -count=1`, `go vet ./...`;
- `node --test tests/browser-metadata.test.mjs tests/radio-player.test.mjs`;
- `node --check` для `web/app.js`, `web/service/radio.js`,
  `web/service/radioPlayer.js` и `web/service/uploadMetadata.js`.

Регрессии проверяют пять реальных будущих позиций на границах циклов, начало
состояния по аудио, предел истории, неизменность encoder при подписках,
multipart/обложку/rollback/удаление, пустую станцию и публичный snapshot.
Настоящий HTTP/FFmpeg-тест держит слушателя при пяти переподключениях и всплеске
20 новых клиентов. Прежние реальные WAV/FLAC/MP3 → MP3 и 29 проверок локальных
метаданных сохранены. Клиентские тесты проверяют гонки переключения, одиночный
retry, offline/online, watchdog и ручную остановку.

В Browser проверены воспроизведение синтетического эфира, раскрытие списков,
обложка/пластинка, светлая/тёмная темы и мобильная ширина 390px; также локальный
разбор синтетического MP3 с обложкой и загрузка через настоящую форму.
`TestRadioBrowserPreview` включается отдельно переменной `RADIOPUMP_PREVIEW=1`,
использует временную БД/музыку на `127.0.0.1:18080` и завершается через 15 минут.
По умолчанию он пропущен. Windows-symlink тест зависит от привилегий, `-race`
не проверен без CGO/C-компилятора. Длительный soak-test и мобильное устройство
с реальной нестабильной сетью не проверены.
